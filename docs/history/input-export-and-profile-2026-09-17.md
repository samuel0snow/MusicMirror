## 先确认数据：2026-09-17

依据输入数据设想图：输入1回答长期实际播放结构；输入2回答主动收藏偏好。最近播放300首是辅助对照来源，不是输入2。

本轮已通过现有API配置输入2并刷新真实账号。取当前红心歌单中`trackIds.at`降序的50首作为**候选测试集合**，逐首验证仍在红心列表；不取歌单原始前50首。`at`的收藏时间语义尚未证实，所以全部`likedAt=null`、`timeWindow=unknown`。API的`source=manual`表示通过显式歌曲列表配置，不代表账号持有人亲自挑选过这些歌曲；本轮由开发测试规则选取，额外来源记录保存在本机`input2-provenance.json`。

这证明输入2配置、采集、计算、持久化与导出链路可用；尚未证明“最近一周/真正最近50首”的自动选择正确。上线前须用账号持有人已知收藏动作核对时间语义，或由用户确认列表；不能用候选样本冒充已验证的近期窗口。

| 可导出字段 | 输入1：长期100首 | 输入2：候选收藏50首 | 解释 |
| --- | --- | --- | --- |
| ID、歌名、歌手 | 100/100 | 50/50 | 合作歌手保留数组 |
| 专辑 | 96/100 | 49/50 | 缺失不推测 |
| 歌曲时长 | 100/100 | 50/50 | 作品长度，不是实际收听时长 |
| 发行时间 | 83/100 | 46/50 | 上游元数据，可能对应再版，不等同首次发行 |
| 曲风、语言 | 0/100 | 0/50 | 现有采集字段无覆盖，不能用歌名或歌手国籍猜测 |
| 当前红心状态 | 100/100可核验 | 50/50均为红心 | 当前状态不是收藏时间 |
| 已验证收藏时间 | 不适用 | 0/50 | 本次不能计算一周内收藏 |
| 分析权重 | Top100内播放次数归一化 | 每首1/50 | 艺人合作分摊，不给多艺人作品额外权重 |

每首还附长期/周计数、最近列表出现标记。长期未上榜时的0仅表示当前Top100中没有计数，不能解释为从未播放；最近列表为unique，`recentPlayCount=1`表示出现，不是只听过一次。Top100不能估计全历史总播放量；作品时长乘次数也不能冒充实际收听时长。

输入2与长期Top100交集8首（16%）；收藏的歌手等权分布中，45.33%的权重落在长期样本未出现的歌手上；艺人JSD约0.6632。这些结果描述两个样本的差异，不能称为“45.33%全新歌手”或“审美已经改变”。

## 本机导出与复现

```powershell
npm run export:account
# 指定另一个仅含一个真实测试账户的数据目录
npm run export:account -- .data/real-test
```

导出脚本读取同一条已保存快照的`normalized_json`与`snapshot_json`，不重新采集、不读取后来修改的输入。输出位置：`<数据目录>/exports/<snapshotId>/`。

- `modules.json`：两个完整模块、逐首特征/权重、字段覆盖率、辅助来源标准化歌曲、算法版本与解释边界。现有六指数标记为未校准MVP结果。
- `input1.csv`、`input2.csv`：逐首明细，UTF-8 BOM，数组用JSON单元格表示；空值不等于0。CSV转义引号/换行并将公式形式名称作为文本；精确原始名称以JSON为准。
- 本次另附`input2-provenance.json`：候选选择方法、未经语义确认的上游at和选取时间；不是已验证收藏时间。它是本轮测试记录，不由通用导出脚本推断生成。

本轮导出验证：JSON与CSV逐首ID/艺人一致，100/50条，权重各自和为1，50条红心验证为true，交集独立重算为8。导出不含账户ID、Cookie、token；歌曲偏好仍属于私人数据，文件只留在忽略提交的`.data`下。

复现配置：登录后向`PUT /inputs/recent-favorites`提交`{"items":[{"songId":"歌曲ID","likedAt":null}]}`（最多50首），再调用`POST /analysis/refresh`，等待run完成后导出。本轮候选列表保存在`.data/real-test/inputs/recent-red-heart/input2-selection.json`。更换输入不会追溯修改旧快照。核验及探测位置见[测试目录说明](../test-data-layout.md)。

## 根据实测确定算法方向

现阶段画像由**行为结构、主动选择、两者差异**构成；音乐内容审美需补充可靠内容特征后再做。保持两个模块的权重独立，避免把收藏歌曲当播放次数混在一起。已有六指数先作为开发诊断，不据此宣称人群排名或确定人格类型。

| 层次 | 采用的计算 | 能给出的解读 | 边界与后续 |
| --- | --- | --- | --- |
| 长期行为结构 | `p_i=c_i/sum(c)`；Top10份额、HHI、有效歌曲数`1/sum(p_i²)`、熵 | 常听样本集中在少数作品，或较均匀分布 | 只覆盖Top100，不能说“什么都听”或证明总体重复倾向 |
| 艺人/专辑结构 | 每首播放权重按合作艺人数均分；维度内归一化；同时报告覆盖率 | 熟悉艺人的作品深度与偏好中心 | 艺人多不等于曲风多；缺失专辑不填虚构类别 |
| 收藏结构 | 每首等权；同样按合作艺人数均分；TopK份额、熵 | 这组主动选择靠近哪些艺人/作品 | 未确认时间之前称“选定收藏”，不称“本周审美” |
| 收藏—实播对照 | 歌曲交集；艺人JSD；各艺人`q_artist-p_artist`；长期样本外艺人权重 | 收藏与常听一致的部分、收藏更突出的偏好 | 长期样本外不是初次发现；JSD不是人格分数 |
| 新旧作品偏好 | 按可靠发行时间计算加权年代分布，附有效样本数 | 两组作品的年代构成差异 | 缺失/再版影响结论；不直接判断“怀旧” |
| 时间变化 | 同算法、同来源规则、可比样本的多次快照，至少3个不同观察时点 | 观察到的偏好结构变化 | 同日重复刷新不构成长期趋势；累计Top100变化慢 |

对照优先输出事实句与证据，如“选定收藏中8首在长期Top100中出现”，并提供歌手权重差异的具体贡献。只凭本账号不能设定“偏离超过多少就属于探索型”的固定标签。下一轮算法迭代先保存分项值、样本数与覆盖率，再以多用户反馈校准阈值；低覆盖或时间未知的维度不生成强解读。

### 下一阶段音乐内容画像

“你的歌单，比你更了解你的音乐审美”中的旋律、人声、节奏、情绪偏好，目前没有足够数据支持。后续须先建立带来源/版本/置信度的歌曲特征表（曲风、语言、节奏、人声等），核验获取权限与准确率，不能让模型仅凭歌名编标签。

特征可靠后，对输入1用播放权重、输入2用歌曲等权分别聚合特征向量；每维只在已知歌曲上归一化，同时保留该维有效权重覆盖率。比较两向量差值并返回贡献歌曲，才能生成“长期常听和主动收藏都偏向某特征”的可追溯解读。先验证多标签曲风/语言，音频情绪和音色分析另设验证阶段，不将艺人身份作为歌曲特征替代物。

本轮决策是先完成数据与可解释统计证据，不重写现有六指数、训练模型或把候选时间固化为正式接口语义。下一步可依据这些导出样本确认画像优先级，再进行算法版本升级。
