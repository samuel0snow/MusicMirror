# 隐私、授权与数据生命周期

依据 [完成指南](design/项目完成指南.md) 第14、18节；这是开发约束，不替代上线前正式隐私政策。

## 收集与保存

| 数据 | 用途 / 保存方式 |
| --- | --- |
| 账户ID、昵称 | 用户绑定与隔离 |
| 网易云Cookie | 服务端请求；AES-256-GCM加密，不进入报告或查询参数 |
| 自有会话token | 客户端访问API；数据库仅存SHA-256摘要，7天到期 |
| 长期/周/近期播放、喜欢ID | 计算与红心验证，按用户隔离 |
| 用户选定近期收藏及可选时间 | 输入2，保存来源；每次快照固定当时输入 |
| 公共歌曲/歌手/专辑元数据 | 增量补全，30天TTL，不含用户Cookie |
| 结构化原始响应 | 去除认证字段后加密，24小时TTL |
| 用户API缓存 | 加密，按用户和端点隔离，来源不同TTL不同 |

不采集密码、音频、人格或心理信息。自动化回归只用合成数据；用户明确授权并扫码确认后才进行真实账号采集，私人响应与凭证不提交到Git。

## 登录、密钥与日志

真实绑定通过配置上游的 `/login/status` 校验；用户ID来自上游，不信任客户端指定。小程序分析页面只接收自有随机token，不接收上游Cookie。现提供二维码登录与备用Cookie绑定；二维码短期会话只用于当前扫码，成功后服务端验证账号再加密存Cookie。二维码上游key与查询凭证不写入日志；本机CLI测试的临时二维码资料放在忽略提交的.data目录。

默认不记录请求体、认证头、Cookie、响应体和上游错误原文。错误只返回稳定代码与安全文案。无ENCRYPTION_KEY时本地生成 `.data/encryption.key`，密钥与SQLite均不提交；密钥和数据库备份必须配套。生产改用独立密钥管理、TLS，并关闭演示登录。

## 用户操作

| 操作 | 语义 |
| --- | --- |
| 退出 | 撤销当前会话，保留绑定和报告 |
| 解绑 | 取消并等待采集，删除Cookie、用户API缓存与原始响应；保留报告 |
| 删除全部数据 | 取消并等待采集，删除账户、全部会话、收藏输入、任务、播放关联、原始响应、快照、洞察 |

公共歌曲元数据可保留；用户关联必须清理。删除后旧token失效，后台任务不能写回。缓存和原始响应在启动及定时清理时删过期行，读取同时检查TTL。

SQLite逻辑删除不等于取证级擦除；生产需明确磁盘、日志和备份保留策略。不得承诺所有历史备份被立即擦除。

未知收藏时间明确标注；收藏不等于播放；置信度表示数据充分程度，不表示心理推断可靠程度。

## 本机研究导出

歌曲百科接口可能返回私人首次收听、记忆、评论、歌词等额外内容；补全仅缓存曲风、语种、BPM、百科发行时间、推荐标签和来源投影，完整百科响应不进入数据库。开发探测曾在忽略提交的.data目录保存临时响应，测试结束应清理这些探测文件。

用户授权的数据核验可输出JSON/CSV到`.data/<数据目录>/exports/`，只输出快照及歌曲特征，不输出账户ID、Cookie或token。导出文件为明文私人偏好数据，不提交Git；不受数据库24小时原始响应TTL管理。账户删除仅清理数据库，不会自动删除已导出的独立文件，测试结束应按需手动清理。候选收藏的上游时间字段与已验证收藏时间明确分开保存。
